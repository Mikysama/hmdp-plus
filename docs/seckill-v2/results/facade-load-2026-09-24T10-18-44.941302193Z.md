# Facade-level comparison

Run: 2026-09-24T10:20:56.809916406Z

This calls the production Java facade directly, with production ShardingSphere and two isolated MySQL instances, isolated Redis, and an embedded Kafka broker. It does not measure HTTP, login interceptors, request-rate limiter, frontend polling, or multi-host capacity. User membership lookup is an in-memory test stub; real inventory, request, operation and Outbox writes run on MySQL. No Kafka delivery/expiry/cancellation runs during the timed admission windows. Each scenario has a fresh stock of 100. Redis scenarios use a 100,000/s token bucket, 256 distributed and local admission slots, and a renewed 5-second lease. `db_accept_calls` measures business transaction entry, not SQL statement count. The database-direct baseline bypasses Redis and passes synthetic qualification records into the same real acceptance transaction, so rejected attempts persist failure rows and release events. It uses fewer requests to bound writes; compare per-request metrics and filtration, not total wall time. Data: facade-load-2026-09-24T10-18-44.941302193Z.csv.
