# HMDP-Plus local benchmark results (2026-09-01)

## Scope

- Endpoint: `GET /shop/1`
- Path under test: Tomcat -> application -> Redis cached shop lookup -> JSON response
- Load model: k6 `constant-arrival-rate`
- Validation: HTTP status is 200 and response field `success` is `true`
- Warm-up: 200 req/s for 10 seconds
- Recorded duration: 30 seconds per load level

This is a same-host loopback benchmark. It is useful for comparing versions of
this project, but it is not a production-cluster capacity claim.

## Environment

- Machine: MacBook Air, Apple M5, 10 cores, 16 GB RAM
- OS: macOS 26.6.2, arm64
- JVM: Temurin OpenJDK 25.0.3, `-Xms512m -Xmx1024m -XX:+UseG1GC`
- Application: Spring Boot 3.5.4, embedded Tomcat, one process
- Data services: MySQL 8.4.11 (two logical databases), Redis 8.10.1, Kafka 4.3.1
- Load generator: k6 2.2.0 on the same host

The highest verified stable point in this run is **15,000 req/s**: all 450,005
requests passed both checks and k6 dropped no scheduled iterations. At the
20,000 req/s target, 576 iterations were dropped, so 20,000 req/s is treated as
the beginning of load-generator/system saturation rather than stable capacity.

## Resume-safe wording

> 使用 Redis 构建商户热点查询缓存，并通过布隆过滤器、空值缓存、互斥锁与双重检查治理缓存穿透和击穿；在 Apple M5 单机同进程压测环境下，缓存命中接口稳定承载约 15,000 QPS，P95 为 0.45 ms、P99 为 8.94 ms，30 秒内 45 万次请求业务成功率 100%。

Always keep the environment qualifier when presenting these figures. For a
stronger engineering report, run k6 on a separate host and add CPU, GC, Redis
latency and network utilization measurements.
